# 商品與規格狀態

商品：0 下架、1 上架、2 永久停產。
規格：0 下架、1 上架、2 缺貨、3 即將下架、4 永久停產、5 預備上架。

- 一般管理者可以設定永久停產；只有有效、已核准且職位為 ADMIN 的登入員工可以解除。後端每次查核目前員工與職位資料。
- 自動商品連動以規格狀態 1／2／3 判定；任一有效販售規格存在即上架，三者皆無才下架。狀態 3 會先依庫存公式檢查是否應下架；狀態 5 不會讓商品自動上架。永久停產商品不參與自動連動。
- 手動將商品上架：已有規格 1／2／3 時保留各規格狀態；否則若有規格 5，只將所有 5 改為 1，不詢問；再否則詢問是否將規格 0 上架。規格 4 一律不連動。
- 沒有規格或只有永久停產規格的商品，必須先新增規格或由 ADMIN 解除規格停產，才能上架。
- 手動將商品下架（含本頁批次）：規格 1／2／3／5 全部改為 0；規格 4 保持不變。批次略過永久停產商品。
- 規格 3 的「庫存＋待進貨－待出貨」小於或等於零時，規格自動改為 0。規格編輯與結帳扣庫存後均使用此條件。
- 狀態與庫存修改在同一個交易內完成；批次需要確認時，整頁不會先部分套用。商品上架的規格確認不可使用「今天不再提示」略過。

主要程式：ProductLifecycleService、ProductStatusAccess、ProductService、ProductSkuService。
結帳：OrdersService／SkuStockRepository；先鎖商品，再依序鎖規格。
畫面確認：admin/js/product-status.js；後端 409 表示需要確認，再以 activateSkus=true 重送。

新增狀態沿用現有 TINYINT 欄位，沒有修改資料表結構或批次重寫既有商品狀態。
